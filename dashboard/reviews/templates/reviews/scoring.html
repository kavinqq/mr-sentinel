欄位說明

window_days評分看最近幾天的 MR
min_reviewed_mrs個人 MR 少於這個數就不給等級
followup_days上線後幾天內的 fix / 新 finding 算後續 bug
finding_capMR 上留下的 finding 讓該面向最多幾分(high / medium / low)
escape_incrementmerge 時還沒修,該面向再扣幾分(依嚴重度)
followup_increment確認的後續 bug 再扣幾分(fix_mr / ai_refind);未確認的不扣
prior_strength / prior_score每項向 prior_score 收縮的強度,等於幾個「prior_score 分」的虛擬 MR(越大越難拿高分)
item_max每項滿分(總分 = 8 × 已評估各項平均)
required_items這些面向沒評估到就是「資料不足」,不給等級。可用:{% for k, v in categories.items %}{{ k }}({{ v }}){% if not forloop.last %}、{% endif %}{% endfor %}
levels由好到差;每一級的條件全部都要符合才算。最後一級 min_score 為 null
　min_score / min_item總分下限 / 最弱一項下限
　min_coverage / min_mrs至少幾個面向已評估 / 至少幾個 MR 已打分
　max_high / max_escaped / max_confirmed_followups窗口內 high finding / merge 時沒修 / 確認的後續 bug 最多幾個(可省略)
　min_clean_rate沒有任何計分 finding 的 MR 比例下限,0.9 = 90%(可省略)
