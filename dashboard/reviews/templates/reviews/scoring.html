欄位說明

window_days評分看最近幾天的 MR
min_reviewed_mrs被 review 的 MR 少於這個數就不給等級
item_max每個面向的滿分(8 項,總分 = 8 × 這個數)
deduction_per_weight每項扣分 = 這個數 × 該項加權問題 / MR 數(越大越嚴)。4 = 10 個 MR 有 1 則 Medium,該項扣 0.8
severity_weight每則 finding 依嚴重度的權重(high / medium / low)
category_multiplier各面向每則 finding 的倍率,沒列出的 = 1。可用:{% for k, v in categories.items %}{{ k }}({{ v }}){% if not forloop.last %}、{% endif %}{% endfor %}
escape_multipliermerge 時還沒修的 finding 再加扣幾倍(1 = 總共扣兩次)
followup_weight每筆後續 bug 的權重(fix_mr / ai_refind),算進對應面向:AI 再次抓到 → 該 finding 的面向,fix MR → 正確性
unconfirmed_followup_factor還沒人確認的後續 bug 算幾成(0.5 = 一半);確認 = 全額,「不是同一個問題」= 0
followup_days上線後幾天內的 fix / 新 finding 算後續 bug(下次同步重算)
levels由好到差;每一級的條件全部都要符合才算。最後一級 min_score 為 null
　min_score總分下限(由高到低遞減)
　min_item最弱的那一項至少幾分(可省略)
　max_high窗口內 high finding 最多幾則(可省略)
　max_fix_mr上線後被 fix MR 修最多幾次(可省略)
　max_escapedmerge 時還沒修的 finding 最多幾則(可省略)
　min_clean_rate沒有任何計分 finding 的 MR 比例下限,0.9 = 90%(可省略)
