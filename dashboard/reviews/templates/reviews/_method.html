help評分方式公式 v{{ version }} · 可在「評分設定」調整

1 · 每個 MR 逐項打分

AI 讀 diff 與 MR description,8 個面向各打 1–5 分,要附證據:

  • 5 範本等級,至少 2 個可定位的證據
  • 4 好,至少 1 個證據
  • 3 合格,可以 merge 但沒有亮點
  • 1–2 有缺口 / 失守
  • 跟這個 MR 無關的面向標「不適用」,不計分

2 · finding 與上線後

  • review 留下的 finding 限制該項上限:High ≤ {{ cfg.finding_cap.high }}、Medium ≤ {{ cfg.finding_cap.medium }}、Low ≤ {{ cfg.finding_cap.low }}
  • merge 時還沒修:再扣 High {{ cfg.escape_increment.high }} / Medium {{ cfg.escape_increment.medium }} / Low {{ cfg.escape_increment.low }}
  • 確認的後續 bug:再扣 {{ cfg.followup_increment.fix_mr }};未確認的只顯示、不扣分
  • 最低 1 分

3 · 個人每項與總分

每項 = ( {{ cfg.prior_strength }} × {{ cfg.prior_score }} + Σ 各 MR 分數 ) ÷ ( {{ cfg.prior_strength }} + MR 數 )

  • 等於先放 {{ cfg.prior_strength }} 個 {{ cfg.prior_score }} 分:MR 越少越接近 {{ cfg.prior_score }},幾個 MR 定不了生死
  • 打過分的 MR 少於 5 個標「樣本少」,少於 15 個標「暫定」
  • 總分 = 8 × 已評估各項的平均(滿分 {{ max_total|floatformat:0 }}),沒評估過的面向顯示「—」
  • 前端、後端各算一條,總分依打過分的 MR 加權;兩條都達 {{ cfg.fullstack_min_score }} 分另加 {{ cfg.fullstack_bonus|floatformat:0 }}(只顯示,不影響等級)
